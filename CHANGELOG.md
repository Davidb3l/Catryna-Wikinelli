# Changelog

## Unreleased

## 1.3.1 — 2026-10-12

- Fixed: **the plugin's MCP server now starts on Windows.** Installed 1.3.0 copies launch it with a bare `"command": "bash"`, which on Windows outside Git Bash resolves to `C:\Windows\System32\bash.exe` (the WSL launcher) and dies, so Claude Code showed `catryna` as CONNECTION_CLOSED. The fix (`bun run ${CLAUDE_PLUGIN_ROOT}/scripts/run-server.ts`, no shell) was already on `main` but still carried version 1.3.0, and Claude Code's plugin updater is version-keyed, so installed copies never received it. This release bumps the version so `/plugin update` delivers it. `scripts/run-server.sh` remains as a thin shim over the same launcher. The first-run dependency install now also heals a partial `node_modules/` left by an interrupted install.
- Changed: the SessionStart and Stop hooks no longer need a POSIX shell. `hooks/hooks.json` ran `sh check-catryna.sh` and `sh drift-check.sh`, and a bare `sh` is absent outside Git Bash on Windows. Both are now Bun TypeScript (`scripts/check-catryna.ts`, `hooks/drift-check.ts`, logic in `src/hooks.ts`) with the same messages, silence rules and never-blocking contract (always exit 0, failures swallowed). They print on stdout, where the old `2>&1` put them. The `.sh` versions are removed.
- Changed: the missing-suite-tools hint now points at the Sothis suite (`/plugin marketplace add Davidb3l/Sothis`, `/plugin install sirius@sothis`, `/plugin install hayvenhurst@sothis`, and `sothis install --profile docs` for the CLIs) instead of the retired per-tool marketplaces. The README documents the suite route `catryna@sothis` next to the standalone `catryna@catryna-wikinelli`.
- Fixed: drift no longer reads a changed file as clean when its name is not ASCII. Git quotes such paths by default (`"src/caf\303\251.ts"`), so the changed-file set never matched the anchor (`src/café.ts`). Drift now reads every file list with `-z`: the changed-file sets, rename detection for broken anchors, and the uncommitted-file count.
- Fixed: drift's diff parsing no longer depends on the user's git config. `color.diff=always` put ANSI escapes into hunk headers, `diff.noprefix=true` dropped the `a/` `b/` prefixes, and `diff.external` / textconv drivers rewrote the output. Every diff drift parses or hands to an agent now passes `--no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/`.
- Fixed: a corrupt or merge-conflicted `.docs/_index.json` is no longer silently replaced by an empty index. Storage creates an index only when the file is absent. If it exists but does not parse, the write tools and every read path fail with an error naming the file (and saying so when it holds `<<<<<<<` conflict markers), and the file is left untouched. A failed parse is re-read a few times first (a torn read), and transient Windows `EBUSY`/`EPERM`/`EACCES` reads are retried briefly. `catryna drift` reports the error instead of printing a clean bill of health.
- Fixed: two processes breaking the same stale index lock could delete a live lock that had replaced it, leaving two holders. The stale lock is now renamed to a unique tombstone (atomic, so one waiter wins), verified to be the lock that was judged stale, and put back if it was not.
- Fixed: the viewer's `POST /api/projects/select` is no longer open to cross-site requests. It requires `Content-Type: application/json` (415 otherwise) and rejects a request whose `Origin` header is not the viewer's own loopback origin (403).
- Fixed: `GET /api/projects?x=1` is the project list, not a 404. Viewer search no longer matches the text "undefined" for an untitled doc, and the command palette shows the doc's path name for it.
- Fixed: `setFrontmatterScalars` (used by `verify` and `consume`) now writes an empty frontmatter block (`---` / `---`) and a block whose closing `---` is the last line of the file, instead of silently skipping the `.mdx`.
- Added: `catryna --version` (also `-V` and `catryna version`) prints `catryna <version>` and exits 0. It used to print the usage text and exit 2; the Sothis suite doctor probes every tool with `<cmd> --version`.
- Changed: the prerequisite is Bun 1.2 or newer (the lockfile is the text `bun.lock`), declared as `engines.bun` in `package.json`. The README now says CI gates Ubuntu, macOS and Windows.
- Added: community health files (CONTRIBUTING, CODE_OF_CONDUCT, SECURITY), issue and PR templates including a "Drift got it wrong" report, CI and license badges and a Sothis suite link in the README, and GitHub Discussions for questions (CAT-9).
- Fixed: a dependency in an incompatible language no longer drifts a doc. When Hayvenhurst reports a call across language families (e.g. Rust `migrate` → TS `close`, a bare-name edge), drift ignores it. Unknown extensions are kept, and C, Rust, Swift and Go count as one C-ABI group. Known costs: real bindings outside that group (PyO3, napi, JNI, …) no longer drift a doc on the Hayvenhurst path, and a bogus same-name edge inside it still does. This guards Catryna until Hayvenhurst fixes the edges upstream (HAYV-18) (CAT-10).
- Fixed: drift no longer flags a doc when another file's same-named symbol changes. Hayvenhurst symbol anchors now resolve to the node in the anchored file, and fall back to git-diff when there's no such node. Every exact-name match among the top 200 `hayven query` hits is checked (CAT-5).
- Added: CI runs the full gate (backend + viewer typecheck, tests, doc lint, drift) on every push and PR, on macOS, Ubuntu and Windows (CAT-11).
- Fixed: the symlink containment tests no longer fail on Windows machines without Developer Mode. A directory link is a junction there (no privilege needed, and still resolved by realpath), and a file-symlink test reports as skipped when the host can't create one, instead of failing with EPERM.
- Fixed: on a Windows (CRLF) checkout, the viewer no longer renders each doc's frontmatter (`---`, `id:`, `verifiedCommit:`, …) as the doc's opening paragraphs. The viewer's MDX parser now normalizes line endings, as the backend's already did.
- Fixed: doc paths are now validated. Every doc read, write and delete (the MCP tools, `verify`, `consume`, `repair`, `lint`) must resolve to a file inside `.docs/`, on resolved real paths, using portable `/`-separated names that every OS can store. `catryna lint` reports an index entry whose path doesn't as `invalid-path`, and `verify` refuses it (CAT-13).
- Fixed: the Stop-hook tests no longer time out on slow Windows CI runners. Each one spawns the hook, which runs `bun` three times, and a loaded runner pushed single tests past Bun's 5s default. The file now sets a 30s budget like the repo's other subprocess-heavy suites.
- Fixed: a flaky viewer test ("a 7-char lowercase hash prefix resolves; short or uppercase forms are 400"). It uppercased the first 10 characters of a fixture commit hash, and when those were all digits (about 1 in 100 commits) nothing changed, so the API correctly answered 200. The uppercase form now always reaches a letter (CAT-16).
- Fixed: on Windows, concurrent index writes (e.g. parallel `catryna verify` processes) no longer lose each other's updates. A lock file mid-delete makes Windows report EPERM, EACCES or EBUSY rather than EEXIST, and the index lock treated those as "can't lock here" and wrote unlocked. They now mean "held, retry" while a lock file is present; with none present they get a 1s grace, then fall back as before. Releasing the lock retries on the same codes (CAT-15).
- Fixed: on a Windows (CRLF) checkout, `catryna verify` and `catryna consume` now write the `.mdx` frontmatter as well as `_index.json`. The frontmatter rewrite only matched LF line endings, so it silently skipped the file and the record and the index diverged. It now keeps the file's own line endings and leaves the body byte-for-byte unchanged. `catryna lint` warns (`index-mismatch`) when a doc's frontmatter `verifiedCommit` disagrees with the index; re-run `catryna verify` on such a doc (CAT-14).
- Fixed: the docs viewer binds `127.0.0.1` by default; set `CATRYNA_VIEWER_HOST` (e.g. `0.0.0.0`) to expose it on the network. Its doc and index reads now require the resolved real path to be inside the served `.docs/` (CAT-12).
