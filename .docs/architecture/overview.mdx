# Architecture Overview

Catryna Wikinelli is a file-based documentation platform designed for both AI coding agents and humans. The key insight is that documentation is stored as .mdx files in the .docs/ folder, enabling dual access: AI agents can read docs directly via file system, while MCP tools handle mutations (create/update/delete).

Docs are not just stored — they are ANCHORED to code and checked against it. That drift machinery (anchors, baselines, the `catryna` CLI, the suite event spine) is the second half of the architecture below.

## Core Architecture

The system has five parts:

1. **MCP Server** (`src/index.ts`, bin `catryna-mcp`) - A Bun-run server using the Model Context Protocol SDK that exposes 15 tools for documentation management. Runs on stdio for Claude Code integration.

2. **CLI** (`src/cli.ts`, bin `catryna`) - A SEPARATE entry point from the MCP server, with hand-rolled arg parsing and six subcommands: `doctor`, `drift`, `lint`, `verify`, `repair`, `consume`. This is what CI, the Stop hook, and peer suite tools invoke.

3. **Drift engine** (`src/drift.ts`) - Classifies every anchored doc against git as `broken`, `drifted`, `unverified`, or `clean`, using each doc's `verifiedCommit` baseline. Optional Hayvenhurst symbol precision; git-diff fallback always works with zero dependencies. Change sets are computed **once per distinct baseline** and intersected per doc, rather than one `git diff` per doc — 300 docs dropped from ~2,230ms to ~38ms. An additive `only` filter narrows a run to named docs — which docs are evaluated, never how one is judged (the hayven symbol universe is built from the **full** corpus for exactly this reason; deriving it from the filtered set let a filtered read report `clean` for a doc the full run called `drifted`) — so a single-doc read costs one doc's git work instead of a corpus scan. Runs under Bun **or** Node (`runGit` / `runHayven` feature-detect), because the viewer's Vite plugin imports this engine in a context with no `Bun` global. The dispatch is an exported seam (`selectGitRunner` / `hasBunSpawn` / `runGitViaBun` / `runGitViaNode`) precisely so it is testable: `Bun` is a non-configurable global a test cannot hide, and testing the fallback in isolation proved it worked while a Bun-only revert stayed green.

4. **Suite spine** (`src/events.ts`, `src/consume.ts`) - Append-only JSONL event log at `.suite/events/<UTC-day>.jsonl`. Catryna EMITS `doc.created` / `doc.updated` / `doc.drifted` / `doc.verified`, and CONSUMES hayven `code.changed` events to mark docs drift-suspect between full drift runs.

5. **Frontend Viewer** - A React/Vite application (port 1307, overridable via `CATRYNA_VIEWER_PORT`) that provides a visual interface for humans to browse, search, and view documentation. Its dev API also serves `GET /api/coverage` and `GET /api/drift`, which drive the verified badge and the coverage dashboard.

### The trust surface (Phase 2)

Two shared, root-parameterized modules sit between the engine and every consumer, so the CLI, the MCP tools, and the viewer cannot disagree:

- **`src/freshness.ts`** — a read-only projection over the drift engine, with a HEAD+index-keyed cache on the read path only (the CLI gate always re-measures). Attaches a status and a one-line warning to `get_doc` / `list_docs` / `search_docs`, so an agent is warned *before* trusting a stale doc. Adds `unanchored` and `unknown` so a doc with no verdict is never reported as clean.
- **`src/coverage.ts`** — coverage over **effective anchors**, shared by the MCP tools and `GET /api/coverage`. Takes every root as a parameter and never reads `process.cwd()`.
- **`src/lint.ts`** — the STRUCTURAL question (`catryna lint`), which drift cannot answer: unparseable frontmatter, orphaned callout tags, unclosed fences, **empty** fences (balance is not content — a doc can be structurally perfect and entirely hollow), **volatile facts** in prose (a repo-wide number/version that no anchor can police, so it rots invisibly), anchors that resolve to nothing, index/file disagreement. Human mode exits 3 like drift; `--json` always exits 0 (a report, not a gate); `verify` refuses to baseline a structurally malformed doc.

- **`src/tokens.ts`** — the answer to the volatile fact lint flags: **computed-fact tokens** a doc carries as a query (`{{count: src/*.rs}}`, `{{loc: src/}}`, `{{version: Cargo.toml}}`), evaluated at read time by `get_doc` and the viewer so the number is regenerated from the live tree and cannot go stale. A read-only allowlist contained to the project root — never a shell. See [features/computed-facts](../features/computed-facts).

### Enforcement

The gates are only worth having if something runs them. `bun run check` is typecheck + tests + lint + drift behind one exit code (~14s), `scripts/install-hooks.sh` installs a **pre-push** hook that runs it, and the Stop hook reports drift *and* lint advisorily without ever blocking a session. All local — no CI service, nothing over the network.
- **`src/trend.ts`** — coverage over time, computed from git history (each commit's file tree + its `.docs/_index.json`) rather than a persisted series. No new state, no write side-effect, and full retroactive history. Shares path classification with `src/coverage.ts` so the newest sample always equals live coverage at HEAD.

Discovery across the suite goes through `src/doctor.ts`: `catryna doctor --json` emits the SUITE_CONTRACTS §3 handshake envelope (`{tool, version, schemaVersion, ok, capabilities, ui, checks, report}`), advertising the capabilities that exist today — `mcp`, `events.emit`, `events.consume`, `drift`, `verify`, `ui`.

## Data Flow

**Claude Code (AI Agent):**

- READ: Direct file access to .docs/{path}.mdx - no MCP needed

- WRITE: Uses MCP tools (create_doc, update_doc, delete_doc)

- CHECK: Uses MCP tools check_drift / verify_doc / propose_doc_repair, without shelling out

**Frontend (Human):**

- READ: Fetches from Vite dev server API that reads .docs/ folder

- WRITE: Currently view-only (edit capabilities in development)

**CLI / CI / hooks:**

- `catryna drift` is a CI gate: exit 3 when a doc drifted or an anchor broke, 1 on operational failure, else 0

- The plugin's Stop hook (`hooks/drift-check.sh`) runs `consume` then `drift --json` and nudges the agent on stderr; it never blocks a session

- `catryna repair` prints the repair context (doc content + anchor diffs) for the agent to act on

## The drift lifecycle

```text
create_doc (+ anchors)  →  catryna verify <path>   # records HEAD as verifiedCommit
        ↓                          ↓
    code changes            catryna drift          # broken / drifted / unverified / clean
        ↓                          ↓
 hayven code.changed  →  catryna consume           # marks docs drift-suspect (real time)
        ↓                          ↓
                       catryna repair / propose_doc_repair
                                   ↓
                        update_doc  →  catryna verify   # re-baseline, doc reports clean
```

An anchor is `{file, symbol?, lines?}`; a bare `relatedFiles` path counts as a file-level anchor, so pre-anchor docs keep drifting with zero migration.

```text
catryna-wikinelli/
├── .docs/                    # Documentation files (git-tracked)
│   ├── _index.json           # Index of all docs (metadata)
│   └── **/*.mdx              # Individual doc files
├── .suite/                   # Suite event spine (SUITE_CONTRACTS §2)

│   └── cursors/catryna.json  # Our consumer cursor
├── src/
│   ├── index.ts              # MCP server entry point (bin: catryna-mcp)
│   ├── cli.ts                # CLI entry point (bin: catryna)
│   ├── doctor.ts             # Suite discovery handshake
│   ├── drift.ts              # Drift engine + verify
│   ├── lint.ts               # Structural doc lint (catryna lint)
│   ├── events.ts             # Spine emit + consume primitives
│   ├── consume.ts            # code.changed → drift-suspect marking
│   ├── storage.ts            # File-based storage layer
│   └── tools/
│       ├── docs.ts           # Document CRUD tools
│       ├── search.ts         # Full-text search
│       ├── diagrams.ts       # React Flow, Mermaid & tldraw

│       ├── lint.ts           # lint_docs — structural doc health

└── frontend/                 # Vite viewer (port 1307)
```

## Key Design Decisions

<Callout type="info">
**File-Based Storage**: Docs are MDX files with YAML frontmatter. This enables direct file reads by Claude, git versioning, and human editability.
</Callout>

<Callout type="info">
**Dual Index**: _index.json maintains metadata for fast listing/search without parsing every MDX file. It is what `catryna drift` queries for the drift fields (`anchors`, `verifiedCommit`, `driftSuspect*`), and each .mdx mirrors them in its frontmatter. Direction matters: for **anchors** the .mdx is the record and the index is a cache, reconciled frontmatter → index by `catryna verify` — otherwise hand-editing a doc's anchors changes nothing that drift ever reads. Index writes take an in-process chain **and** a cross-process lock file, so parallel agents each running `catryna verify` cannot clobber each other's baselines.
</Callout>

<Callout type="info">
**Verification is not editing**: a doc's drift baseline is `verifiedCommit`, never `updatedAt` — rewriting prose does not re-verify a doc against code. Only `catryna verify` / `verify_doc` moves the baseline.
</Callout>

<Callout type="info">
**Degrade, never gate**: spine emission is best-effort, the Hayvenhurst probe is optional, and an absent spine, absent `.docs/`, or missing `hayven` all degrade to a clean no-op instead of an error.
</Callout>
