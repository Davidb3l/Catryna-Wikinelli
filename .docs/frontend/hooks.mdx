# React Hooks

Custom React hooks for data fetching and state management.

## useDocsList

Fetches the list of all documents and builds a navigation tree.

```typescript
const { 
  docs,      // DocMetadata[] - flat list of all docs
  navItems,  // NavItem[] - hierarchical nav tree
  loading,   // boolean
  error,     // string | null
  refetch    // () => Promise<void>
} = useDocsList();
```

Automatically fetches on mount from `/api/docs`. Entries are filtered by `isUsable()` and passed through `normalizeDocMetadata()` before anything else touches them, so `docs` is always fully-populated `DocMetadata` — including the drift fields — regardless of how old the `_index.json` on disk is. The `navItems` are built by `buildNavTree()`, which groups docs by path folders.

The tree is only **one level deep**, despite `NavItem.children` being recursive. `buildNavTree()` keys folders by the doc's full folder path but titles them with the last segment and pushes every folder onto the root array — so `a/b/c` renders as a top-level folder named `b`, not nested under `a`.

## useDoc

Fetches a single document by path.

```typescript
const { 
  doc,       // Document | null
  loading,   // boolean
  error,     // string | null
  refetch    // () => Promise<Document | null> | null | ''
} = useDoc(path);  // path: string | null
```

When `path` is null, returns null without fetching. On 404, sets doc to null without error.

`refetch` is written as `() => path && fetchDoc(path)`, so it returns the falsy `path` rather than a promise when nothing is selected — always guard before awaiting it.

The API response is mapped by `toDocument()`: it normalizes the metadata, splits `path` on `/` into a string array, sets `lastUpdated` to `new Date(updatedAt).toISOString()`, and attaches the doc's drift baseline as `verification`. `history` / `isDraft` are never populated.

## verificationStatus

```typescript
verificationStatus(v: DocVerification | undefined): VerificationStatus
```

Reduces a doc's five drift fields to `'verified' | 'suspect' | 'unverified'` for display. No `verifiedCommit` (or no `verification` at all) is `unverified` — never silently clean, matching `catryna drift`. A set `driftSuspectSince` is `suspect`.

This reads *stored* frontmatter state. For the live, git-computed verdict the badge actually renders, use `useDrift()` below.

## useDrift

Per-doc drift status for the verified badge (Phase 2).

```typescript
const {
  drift,       // DriftResponse | null
  loading,     // boolean
  statusFor,   // (path: string) => DriftStatus | null
  refetch,     // () => Promise<void>
} = useDrift();
```

Fetches `GET /api/drift`, which runs the same git-backed engine as `catryna drift`. `statusFor(path)` returns the verdict for one doc, or `null` when there is none.

<Callout type="warning">
`null` is meaningful and must not be treated as verified. It means the doc anchors no code, or the viewer could not reach the endpoint (no git repo, or an older dev API). Callers render **no badge** in that case rather than a green one — failing to ask is not a clean bill of health. This mirrors the `unanchored` / `unknown` states in `src/freshness.ts`.
</Callout>

The hook degrades quietly: on any error `drift` is `null` and every `statusFor` returns `null`.

## useCoverage

Real documentation coverage, replacing the viewer's former hardcoded placeholders.

```typescript
const {
  coverage,   // CoverageResponse | null
  loading,    // boolean
  error,      // string | null
  refetch,    // () => Promise<void>
} = useCoverage();
```

Fetches `GET /api/coverage`. On failure `coverage` is `null` and `error` is set; `CoverageReport` renders "Coverage unavailable" rather than inventing numbers.

## useCoverageTrend

Coverage over time, from `GET /api/coverage/trend`.

```typescript
const {
  trend,     // CoverageTrendResponse | null
  loading,   // boolean
  refetch,   // () => Promise<void>
} = useCoverageTrend(points = 40);
```

Derived from git history on request — there is no stored series, so the chart is always complete and always current, with no backfill period.

<Callout type="info">
Each sample costs two git reads, so this is the slowest call on the dashboard and lags the other panels on a long history. `loading` matters here: `CoverageReport` shows "Reading coverage from git history…" rather than leaving a blank that reads as "no data".
</Callout>

## useDocsSearch

Search across all documents.

```typescript
const { 
  results,   // DocMetadata[]
  loading,   // boolean
  error,     // string | null
  search     // (query: string) => Promise<DocMetadata[]>
} = useDocsSearch();
```

The `search` function requires a minimum of 2 characters (shorter queries clear the results and return `[]` without a request). Calls `/api/docs/search?q={query}`.

Despite the name, this is not full-text search: the endpoint matches every whitespace-separated term against the doc's **title, tags, and path** from `_index.json` and caps results at 20. Body content is never searched.

## EMPTY_DOC

Default placeholder document shown when no doc is selected:

```typescript
export const EMPTY_DOC: Document = {
  id: 'empty',
  title: 'No Document Selected',
  path: [],
  blocks: [
    { id: 'empty-1', type: 'heading-1', content: 'Welcome to Catryna Wikinelli' },
    { id: 'empty-2', type: 'paragraph', content: 'Select a document from the sidebar...' },
    { id: 'empty-3', type: 'callout', content: 'Use MCP tools to create docs.', metadata: { level: 'info' } },
  ],
  lastUpdated: new Date().toISOString(),
};
```
