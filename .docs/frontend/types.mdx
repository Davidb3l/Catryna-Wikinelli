# Types & Data Models

Type definitions used throughout the Catryna Wikinelli application.

## Block Types

```typescript
type BlockType = 
  | 'paragraph' 
  | 'heading-1' | 'heading-2' | 'heading-3' 
  | 'code' 
  | 'callout' 
  | 'diagram' 
  | 'whiteboard' 
  | 'divider'
  | 'table';

interface Block {
  id: string;
  type: BlockType;
  content: string;
  metadata?: {
    language?: string;           // For code blocks
    level?: 'info' | 'warning' | 'error' | 'success';  // For callouts
    filePath?: string;           // For code embeds
    diagramData?: any;           // React Flow data, or { mermaid: string }
    whiteboardData?: any;        // tldraw data
    headers?: string[];          // For tables
    rows?: string[][];           // For tables
  };
}
```

These are the *viewer's* block types, produced by `parseMdx()` in `frontend/vite.config.ts`. They are not the same vocabulary as the MCP authoring blocks (`heading`, `text`, `markdown`, `mermaid`, …) — the MDX file is the contract between them.

## Document

```typescript
interface Document {
  id: string;
  title: string;
  blocks: Block[];
  lastUpdated: string;     // ISO date string
  path: string[];          // e.g., ["modules", "auth"]
  isDraft?: boolean;
  history?: HistoryEntry[];
  verification?: DocVerification;  // drift baseline, populated by toDocument()
}
```

## Verification (drift state in the viewer)

`frontend/types.ts` mirrors the backend's drift fields so the viewer can tell a verified doc from one the code has outgrown:

```typescript
interface DocAnchor {           // mirrors DocAnchor in src/storage.ts
  file: string;
  symbol?: string;
  lines?: [number, number];
}

interface DocVerification {
  anchors: DocAnchor[];
  verifiedCommit: string;       // "" = never verified
  verifiedAt: string;
  driftSuspectSince: string;    // "" = not suspect
  driftSuspectReason: string;
}

type VerificationStatus = 'verified' | 'suspect' | 'unverified';
```

`verificationStatus(v)` — exported from `frontend/hooks/useDocs.ts`, not from `types.ts`, which stays purely declarative — reduces the five fields to the three states a badge needs: no `verifiedCommit` is `unverified`, a set `driftSuspectSince` is `suspect`, otherwise `verified`.

## Drift and coverage (Phase 2 API types)

These mirror the `GET /api/drift` and `GET /api/coverage` responses.

```typescript
// Mirrors DriftStatus in src/drift.ts.
// clean = green, drifted = amber, broken = red, unverified = grey.
type DriftStatus = 'clean' | 'drifted' | 'broken' | 'unverified';

interface DocDrift {
  status: DriftStatus;
  verifiedCommit: string;
  changedFiles: string[];
  brokenFiles?: string[];      // only when broken
}

interface DriftResponse {
  gitRepo: boolean;
  head: string | null;
  error?: string;
  docs: Record<string, DocDrift>;   // keyed by doc path
  summary: { clean: number; drifted: number; broken: number; unverified: number };
}

interface CoverageSample {
  commit: string;
  timestamp: number;
  coveragePercent: number;
  totalModules: number;
  documentedModules: number;
  totalDocs: number;
}

interface CoverageTrendResponse {
  samples: CoverageSample[];   // oldest first
  totalCommits: number;
  sampled: boolean;            // true when samples is a selection, not every commit
  error?: string;
}

interface CoverageResponse {
  totalModules: number;
  documentedModules: number;
  coveragePercent: number;
  totalDocs: number;
  anchoringDocs: number;
  brokenAnchors: string[];
  undocumented: UndocumentedModule[];  // capped sample
  totalUndocumented: number;           // exact count
  generatedAt: number;
}
```

All three responses are validated by `normalizeDrift` / `normalizeCoverage` / `normalizeTrend` before reaching state. They were previously assigned straight from `res.json()`, so a malformed 200 threw mid-render and — with no error boundary — unmounted the app to a white screen.

<Callout type="info">
`DriftStatus` (the live, git-computed verdict) and `VerificationStatus` (derived from stored frontmatter) answer different questions. Frontmatter records which commit a doc was checked at; only the drift engine knows whether the code has moved on since. The badge uses `DriftStatus`.
</Callout>

## Backend Types (storage.ts)

```typescript
// A validated anchor from a doc to a precise region of code
interface DocAnchor {
  file: string;                // repo-relative path (forward slashes)
  symbol?: string;             // optional symbol inside `file`
  lines?: [number, number];    // optional inclusive 1-based range
}

// Metadata stored in _index.json AND in each .mdx frontmatter
interface DocMetadata {
  id: string;
  path: string;
  title: string;
  tags: string[];
  relatedFiles: string[];      // bare paths == file-level anchors
  anchors: DocAnchor[];        // symbol/line anchors, additive over relatedFiles
  evidence: string[];          // opaque suite URIs backing this doc
  refs: string[];              // opaque suite URIs this doc references
  verifiedCommit: string;      // drift baseline SHA; "" = never verified
  verifiedAt: string;          // ISO-8601 UTC, or ""
  driftSuspectSince: string;   // ISO-8601 UTC set by `catryna consume`, or ""
  driftSuspectReason: string;  // human reason paired with the above, or ""
  createdAt: number;           // Unix timestamp ms
  updatedAt: number;
  createdBy: string;
}

// Full index structure
interface DocIndex {
  version: number;
  docs: DocMetadata[];
  lastUpdated: number | null;
}
```

The anchor/provenance/drift fields (`anchors`, `evidence`, `refs`, `verifiedCommit`, `verifiedAt`, `driftSuspectSince`, `driftSuspectReason`) are additive and backward compatible: absent in a legacy index or frontmatter, they normalize to `[]` / `""` on read. Anchor paths use **forward slashes** on every platform, including docs authored on Windows.

<Callout type="info">
Frontmatter arrays (`tags`, `relatedFiles`, `evidence`, `refs`) are written as single-line **JSON**, and string scalars are JSON-encoded too, so values containing commas, quotes, or backslashes round-trip verbatim.
</Callout>

## What the Viewer Actually Consumes

`frontend/hooks/useDocs.ts` declares its own `DocMetadata` for API responses, mirroring the backend field for field. **Keep the two in sync** — this type is what the viewer can see.

It previously dropped eight fields, including every drift field, which made verification state invisible in the UI and blocked the verified badge. That is fixed: the hook now carries `anchors`, `evidence`, `refs`, `verifiedCommit`, `verifiedAt`, `driftSuspectSince`, `driftSuspectReason`, and `createdBy`.

Two boundary details matter, because the dev API serves `_index.json` verbatim rather than a validated payload:

- **`RawDocMetadata`** (`Partial<DocMetadata> & { path: string }`) types what actually arrives. A legacy index simply omits fields that did not exist when it was written.
- **`normalizeDocMetadata()`** fills those in using the same defaults the backend applies on read (`[]` / `""`), which is why every field on `DocMetadata` is required — consumers never guard. Entries without a usable `path` are dropped first, since `buildNavTree()` and `toDocument()` both split `path` unconditionally.

<Callout type="info">
No component renders verification state yet. The data now reaches the UI layer and `verificationStatus()` derives the badge state, but the badge itself is Phase 2 work.
</Callout>
