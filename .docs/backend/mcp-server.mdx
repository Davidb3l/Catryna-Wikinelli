# MCP Server

The MCP (Model Context Protocol) server is the core backend component that enables Claude Code to interact with the documentation system.

## Entry Point

Located at `src/index.ts` (published as the `catryna-mcp` bin), the server uses the official `@modelcontextprotocol/sdk` package to create a stdio-based server.

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new McpServer({
  name: "catryna-wikinelli",
  version: "1.0.0",
});

// Connect to stdio transport
const transport = new StdioServerTransport();
await server.connect(transport);
```

<Callout type="info">
This is NOT the only entry point. `src/cli.ts` (bin `catryna`) is a separate CLI with the `doctor`, `drift`, `verify`, `repair`, and `consume` subcommands. The MCP server never parses argv; the CLI never speaks MCP.
</Callout>

## Tool Registration

The server registers six tool modules — 15 tools in total:

- **docs.ts** - Document CRUD operations (create_doc, get_doc, list_docs, update_doc, delete_doc)

- **search.ts** - Full-text search across documents (search_docs)

- **diagrams.ts** - Visual content (create_diagram, create_mermaid_diagram, create_whiteboard)

- **coverage.ts** - Documentation metrics (get_undocumented_modules, get_doc_coverage)

- **lint.ts** - Structural doc health (lint_docs) — separate from drift because it answers a different question

- **drift.ts** - Living-docs loop (check_drift, verify_doc, propose_doc_repair)

## Launching

The plugin starts the server through `scripts/run-server.sh`, which resolves the install root, self-heals a missing `node_modules` with `bun install`, then `exec bun run "$ROOT/src/index.ts"`.

<Callout type="warning">
The launcher deliberately never `cd`s before exec: storage resolves `.docs/` from `process.cwd()`, so the server's working directory MUST stay the user's project. An MCP config that pins `cwd` to the Catryna install writes docs into the wrong repo.
</Callout>

## Transport

Uses stdio (standard input/output) for communication with Claude Code. This is the standard transport for CLI-based MCP servers.

<Callout type="warning">
Logs go to stderr since stdout is reserved for MCP protocol messages.
</Callout>

## Side effects on write

The write tools do not only touch `.docs/`. Every durable create/update/verify also appends a past-tense fact to the suite event spine (`.suite/events/<UTC-day>.jsonl`) — `doc.created`, `doc.updated`, `doc.verified` — so peer tools can react. Emission is best-effort: a spine failure is logged to stderr and never fails the doc write.

`catryna doctor` reports the server's presence with its `mcp_entry` check (the resolved path to `src/index.ts`) and advertises the `mcp` capability.
