# MCP Tools Reference

Complete reference for all 15 MCP tools available in Catryna Wikinelli, registered from six modules under `src/tools/`.

## Document Tools (docs.ts)

### create_doc

Creates a new documentation page. Fails (without overwriting) if a doc already exists at `path`.

```typescript
// Parameters
{
  path: string,             // e.g., "modules/auth"
  title: string,            // Human-readable title
  content: Block[],         // Array of content blocks
  tags?: string[],          // Categorization tags
  relatedFiles?: string[],  // Source files covered (file-level drift anchors)
  anchors?: Array<{         // Structured drift anchors, additive over relatedFiles
    file: string,
    symbol?: string,
    lines?: [number, number]
  }>,
  evidence?: string[],      // Suite URIs backing this doc, e.g. "sirius:receipt/89"
  refs?: string[]           // Suite URIs this doc references, e.g. "amt:decision/7"
}
```

`evidence` / `refs` accept any suite scheme and are stored OPAQUELY — never validated or resolved.

### get_doc

Retrieves a document by path. Returns metadata (including `anchors`, `evidence`, `refs`), blocks, and a **`freshness`** object (Phase 2 trust surface). Its blocks are passed through `renderTokensInBlocks` first, so **computed-fact tokens** (`{{count: …}}` / `{{loc: …}}` / `{{version: …}}`) are evaluated against the project root at read time — the agent sees a live number, never a stale one, and a failed token stays raw. See [features/computed-facts](../features/computed-facts).

### list_docs

Lists all documents with optional filtering by tag or path prefix. Each entry carries `freshness`, and the response carries a `warning` headline when any result is stale, broken, or unverified.

### Freshness on reads (Phase 2)

`get_doc`, `list_docs`, and `search_docs` all warn **inline**, so an agent is told a doc is stale *before* it trusts it rather than after acting on it:

```json
"freshness": {
  "status": "drifted",
  "verifiedCommit": "a1b2c3d…",
  "head": "e4f5a6b…",
  "changedFiles": ["src/auth.ts"],
  "summary": "STALE — verified at a1b2c3d, but 1 anchored file(s) have changed since: src/auth.ts. Re-read the code before trusting this doc; run `catryna repair <path>` to fix it."
}
```

Statuses are `clean`, `drifted`, `broken`, `unverified`, plus `unanchored` (the doc anchors no code, so drift cannot be computed) and `unknown` (drift could not run). The last two exist so a read never reports "no verdict" as clean — see the `backend/freshness` doc.

The two list tools resolve their whole result set in a **single** drift pass, not one per entry. All reads pass `emit: false`, so reading never writes to the suite spine.

### update_doc

Updates an existing document's title, content, tags, relatedFiles, anchors, evidence, or refs. Omitted fields are preserved; a provided array REPLACES the existing one.

### delete_doc

Removes a document by path.

## Search Tools (search.ts)

### search_docs

Full-text search across all documents.

```typescript
// Parameters
{
  query: string,  // Search terms (min 2 chars)
  limit?: number  // Max results (default 10)
}
```

Scoring: Title matches (+3), tag matches (+2), path matches (+1), content matches (+1).

## Diagram Tools (diagrams.ts)

### create_diagram

Creates a React Flow architecture diagram.

```typescript
// Parameters
{
  path: string,
  title?: string,
  type?: "architecture" | "flow" | "sequence" | "entity" | "custom",
  nodes: Array<{
    id: string,
    data: { label: string },
    position: { x: number, y: number },
    type?: string
  }>,
  edges: Array<{
    id: string,
    source: string,
    target: string,
    label?: string,
    type?: string
  }>
}
```

### create_mermaid_diagram

Creates a doc containing a single Mermaid diagram (flowchart, sequence, etc.), tagged `diagram` + `mermaid`.

```typescript
// Parameters
{
  path: string,
  title?: string,
  mermaid: string  // Mermaid source
}
```

### create_whiteboard

Creates a tldraw whiteboard document.

```typescript
// Parameters
{
  path: string,
  title?: string,
  snapshot: object  // tldraw snapshot data
}
```

## Coverage Tools (coverage.ts)

### get_undocumented_modules

Finds source files that aren't linked to any documentation.

```typescript
// Parameters: { rootDir?: string, patterns?: string[] }
// Scans for: .ts, .tsx, .js, .jsx, .py, .go, .rs
// Excludes: node_modules, .test./.spec., dist/, build/, __pycache__, .docs/
```

### get_doc_coverage

Generates a coverage report with metrics:

- `totalModules` - Number of source files

- `documentedModules` - Files with linked docs

- `coveragePercent` - Documentation coverage %

- `totalDocs` - Number of docs in the index

- `anchoringDocs` - Docs that anchor at least one file — the ones coverage can credit

- `brokenAnchors` - Anchored paths not present on disk

- `recentlyUpdated` - The 5 most recently updated docs

- `staleDocs` - Docs not updated in 30+ days

- `undocumentedFiles` - List of files needing docs (capped)

- `totalUndocumented` - Exact count, never capped

Both tools delegate to `computeCoverage()` in `src/coverage.ts`, which is shared with the viewer's `GET /api/coverage` so the two never disagree. See the `backend/coverage` doc.

<Callout type="info">
Coverage counts **effective anchors**, so a doc anchored purely through structured `anchors` counts for the files it anchors. This was previously not the case — the tools read `relatedFiles` only, which meant using the more precise Phase 1 anchors made your coverage number worse.
</Callout>

<Callout type="warning">
`recentlyUpdated` / `staleDocs` sort on `updatedAt`, which is **edit** time, not verification time. A recently edited doc is not a verified one — that is what `freshness` and `catryna drift` answer.
</Callout>

## Lint Tools (lint.ts)

### lint_docs

Are the docs **well-formed**? Frontmatter parseable, callout/fence balance, anchors that resolve, index and file in agreement. Returns the same JSON body as `catryna lint --json`.

Separate from the drift tools by design — drift asks whether the code moved, lint asks whether the doc is sound. See the `backend/lint` doc.

## Drift Tools (drift.ts)

The in-session half of the living-docs loop — the same logic behind the `catryna drift` / `verify` / `repair` CLI subcommands, so an agent never has to shell out.

### check_drift

Takes no parameters. Returns the full drift report as JSON for the current working directory: `summary` counts plus the `broken`, `drifted`, `unverified`, and `clean` buckets, whether Hayvenhurst symbol precision was used, and `dirtyFiles` — how many files are modified but not committed, which is work drift structurally **cannot** see (it walks committed history). Read-only — it never emits `doc.drifted` on the spine (the CLI gate and Stop hook own emission).

### verify_doc

Records the repo's current HEAD as a doc's drift baseline (`verifiedCommit` + `verifiedAt`), clears any drift-suspect marker, and emits `doc.verified`. Warns via `brokenAnchors` when an anchored file no longer exists — a warning, not a failure.

It also reconciles the `.mdx` frontmatter's `relatedFiles`/`anchors` into `_index.json`, which is what makes a hand-edited anchor take effect (drift reads the index). A field written in a form the frontmatter parser cannot decode — a YAML block sequence, a flow mapping — is left alone and reported in `unsyncedAnchorFields`, never mistaken for an empty list, since adopting that would delete the doc's working anchors. See the `backend/storage` doc.

```typescript
// Parameters
{
  path: string  // Doc path to re-baseline, e.g. "modules/auth"
}
```

### propose_doc_repair

Returns the REPAIR CONTEXT for drifted docs: the current `.docs/<path>.mdx` content plus the `git diff <verifiedCommit>..HEAD` of each changed anchor. A repair flagged `broken: true` means an anchored file was deleted or renamed (see `brokenFiles`) — there is no diff, the fix is to update the doc's anchors. Carries `dirtyFiles` for the same reason `check_drift` does: repairing against an uncommitted tree means working from an undercount.

```typescript
// Parameters
{
  doc?: string,   // Doc path, or "all" (default)
  since?: string  // Baseline override: commit-ish or ISO date, e.g. "2026-02-18"
}
```

<Callout type="info">
This tool NEVER edits a doc. It hands the agent reviewable context; the agent proposes the change via `update_doc`, then re-baselines with `verify_doc` (or `catryna verify <path>`) so the doc reports clean again.
</Callout>
